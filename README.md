# کلاس آنلاین بلادرنگ با mediasoup

سرویس سبک کلاس آنلاین: دو صفحهٔ HTML (`teacher.html`، `student.html`)، سرور Bun + ElysiaJS و mediasoup (SFU).
**هیچ داده‌ای ذخیره نمی‌شود**: بدون دیتابیس، Redis، کش، فایل یا ضبط جلسه؛ همهٔ وضعیت کلاس فقط در RAM است.

## اجرا

### با Docker
```bash
cp .env.example .env      # TEACHER_KEY و RTC_ANNOUNCED_IP را تنظیم کنید
docker compose up --build
```
- استاد: `http://localhost:3000/teacher.html`
- دانش‌آموز: `http://localhost:3000/student.html?room=<کد کلاس>`

### بدون Docker (توسعه)
```bash
cd server
bun install
bun run build:client      # mediasoup-client، pdf.js و فونت را در client/vendor قرار می‌دهد
TEACHER_KEY=secret bun run src/index.ts
bun test                  # آزمون یکپارچهٔ سیگنالینگ
```
مرورگر فقط روی `localhost` یا **HTTPS** اجازهٔ میکروفون، دوربین و اشتراک صفحه می‌دهد.

## معماری
```
مرورگر ──WebSocket /ws──► Elysia (سیگنالینگ + پیام‌های کنترلی: چت، سؤال، دست بلند، مجوز)
مرورگر ◄──RTP/SRTP UDP|TCP──► mediasoup Worker (SFU) ← Router جدا برای هر کلاس
```
- **مسیر رسانه (mediasoup):** صدای استاد، دوربین، صفحهٔ اشتراکی (+صدا)، خروجی تخته (`canvas.captureStream`) و صدای دانش‌آموز مجاز.
- **مسیر کنترل (WebSocket):** چت، پیام خصوصی، سؤال و پاسخ، دست بلند، مجوز صحبت، حضور، اطلاعات صفحهٔ PDF/ابزار.
- هر کلاس یک `Room` مستقل (Router و Transportهای جدا). هر شرکت‌کننده یک Transport ارسال (فقط در صورت نیاز) و یک Transport دریافت دارد؛ Consumer فقط برای منبع‌های مجاز ساخته می‌شود.
- **اشتراک صفحه و تخته جایگزین هم‌اند:** سرور در هر لحظه یک حالت (`idle | screen | board`) نگه می‌دارد و با فعال‌شدن یکی، Producerهای دیگری را می‌بندد.
- **مجوزها در سرور:** تولید صدا برای دانش‌آموز بدون مجوز رد می‌شود (حتی با دستکاری JS)، همچنین کارهای استاد، پاسخ دوباره به سؤال (بر پایهٔ شناسهٔ مرورگر، حتی پس از قطع و وصل)، و مقصد پیام خصوصی.
- **احراز هویت (فقط توسعه‌ای):** استاد با `TEACHER_KEY` سرور وارد می‌شود. نقطهٔ اتصال به سامانهٔ بیرونی تابع `authenticate()` در `server/src/permissions.ts` است. این روش برای محیط عمومی امن نیست.
- **پاک‌سازی:** با قطع اتصال Transportها (و Producer/Consumerها) بسته می‌شوند؛ heartbeat هر ۱۰ ثانیه و بررسی دوره‌ای کاربران خیالی؛ با پایان کلاس همه‌چیز آزاد و Room حذف می‌شود.

## پورت‌ها و شبکه
| پورت | پروتکل | کاربرد |
|---|---|---|
| `PORT` (3000) | TCP | HTTP + WebSocket |
| `RTC_PORT_MIN … RTC_PORT_MIN+WORKERS-1` (پیش‌فرض ۴۰۰۰۰–۴۰۰۰۱) | UDP **و** TCP | رسانهٔ WebRTC |

- `RTC_ANNOUNCED_IP` باید IP‌ای باشد که مرورگرها به آن می‌رسند (روی سرور ابری: IP عمومی). مقدار اشتباه = اتصال برقرار می‌شود ولی رسانه نمی‌رسد.
- در فایروال/NAT همین پورت‌ها را باز و به میزبان هدایت کنید. تعداد worker را با `MEDIASOUP_WORKERS` تغییر دهید و `RTC_PORT_MAX` را هم به‌روز کنید.
- **HTTPS/WSS:** در محیط عمومی پشت یک reverse proxy (مثلاً Caddy: `reverse_proxy class:3000`) قرار دهید؛ پورت‌های رسانه مستقیماً باز می‌مانند و از proxy عبور نمی‌کنند.
- **TURN:** پشت NAT/فایروال‌های سخت‌گیر ممکن است لازم باشد. سرور TURN (مثلاً coturn) را جدا راه بیندازید و در `ICE_SERVERS` بدهید؛ در این نسخه خود TURN ارائه نمی‌شود. اتصال TCP پورت mediasoup به‌عنوان جایگزین فعال است.

## راهنمای آزمایش (یک استاد + چند دانش‌آموز)
1. استاد را باز کنید، کد کلاس و کلید را بدهید، «شروع کلاس». میکروفون و تخته خودکار شروع می‌شوند.
2. در دو تب/دستگاه دیگر با پیوند «پیوند دانش‌آموز» دو دانش‌آموز وارد کنید. صدا (کلیک ورود لازم است) و تخته را بررسی کنید.
3. «اشتراک صفحه» را بزنید؛ تخته متوقف و صفحه نمایش داده می‌شود؛ با «تخته» برگردید. دوربین را روشن کنید (در کادر کوچک).
4. فایل PDF/تصویر را باز کنید، روی آن بنویسید، صفحه را عوض کنید.
5. چت عمومی و خصوصی (دانش‌آموز → استاد و پاسخ استاد از فهرست). چت را غیرفعال کنید.
6. «سؤال جدید» ارسال کنید؛ دانش‌آموز دوم را بعد از ارسال وارد کنید (باید سؤال را ببیند)؛ پاسخ دوم باید رد شود.
7. دست بلند کنید → تأیید → صدا باید به استاد و دیگران برسد؛ مجوز را لغو کنید.
8. تب دانش‌آموز را ببندید → از فهرست حذف می‌شود. «پایان کلاس» → همه بسته می‌شوند. سرور را ری‌استارت کنید → هیچ اطلاعاتی بازیابی نمی‌شود.

## محدودیت‌های شناخته‌شده
- فقط یک استاد برای هر کلاس؛ اگر سرور ری‌استارت شود کلاس‌های فعال از بین می‌روند (پذیرفته‌شده).
- صدای سیستم/تب هنگام اشتراک صفحه فقط در مرورگرهای مبتنی بر Chromium (و فقط برای برخی انتخاب‌ها) ممکن است؛ در صورت نبود، به استاد پیام داده می‌شود.
- تخته تا زمانی که زبانهٔ مرورگر استاد باز است تصویر می‌فرستد؛ اگر تب در پس‌زمینه برود مرورگر نرخ فریم را کم می‌کند. تب استاد را در پیش‌زمینه نگه دارید.
- سؤال همزمان با ارسال فعال می‌شود (ذخیرهٔ سؤال برای بعد وجود ندارد). تصویر سؤال تا حدود ۶۰۰ کیلوبایت (در مرورگر فشرده می‌شود).
- دست بلند کردن همان «درخواست صحبت» است. سقف هم‌زمان گویندگان با `MAX_SPEAKERS`.
- ICE restart و کدگذاری چندلایه (simulcast) پیاده‌سازی نشده؛ پس از قطع اتصال، صفحه از نو وارد می‌شود و رسانه را دوباره می‌سازد.
- کلید استاد توسعه‌ای است؛ برای محیط عمومی باید با سامانهٔ احراز هویت بیرونی جایگزین شود.
